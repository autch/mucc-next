mucc-next
=========

P/ECE 標準音源ドライバのミュージックデータコンバータ、mucc を改良したものです。

## 改良点

- パートをまとめ書きした際に二つ目以降のパートをコールする構造をやめ、各パートがそのコンテキストでコンパイルされるようにした
  - まとめ書きの多い MML ではファイルサイズが大きくなるかも
  - まとめ書きはないが行数の多い MML では mucc より小さくなるかも
- データはあるが音符や休符のない (= 0tick) パートを出力しないようにした
  - そのようなパートにループやリピートがあると muslib が無限ループする
  - これで困るのは `t` ぐらいだろう 
- 構文エラー検出と表示の強化
  - エラーを見つけた時点で中止し、演奏データを出力しない (後述)
- パート拡張対応
  - 32 パートまで。MML のパート表記は A...Z までなので書ききれない
  - 未使用のパートは出力データに含まれないようにする。結果 MML 上の `'A' + n` パートが出力データの n 番目のパートに対応するとは限らなくなった。
  - 互換性のためデータが 6 パートに満たない場合はカラのパートを追加する。
  - 拙作 [auPiECE.kpi の extended-channels ブランチ](https://github.com/autch/auPiECE.kpi/tree/extended-channels), 同 [pceplayer.js](https://github.com/autch/pceplayer.js/tree/modernize-2024), 同 [fpkplay](https://github.com/autch/fpkplay) で再生できます。
- `l` コマンドに付点 `.` を書けるようにした
- 拡張パート表記 `?`
  - それまでに言及したことのあるすべてのパートに対応する
```
ABC ...
HIJ ...

? L    ; ABCHIJ に対応する。ABCDEFGHIJ ではない

ABC ...
HIJ ...
```
- 拡張コマンド `S`
  - それを書いたパートのその時点のクロックやオクターブ等を表示する
```
line 10: PART A TICK 24  TR_ATTR 0 OCT 4+0 LEN 24+0 VOL 120+0 EXP 0 DETUNE 0+0 XPOSE 0 REP_NEST 0
```
  - 順番に、
    - `line` 行番号
    - `PART` パート名
    - `TICK` そのパートの現在クロック
    - `TR_ATTR` トラック属性、`1` のときドラムパート
    - `OCT` オクターブ、`n+m` で n が `on` の値、m が `o+m` の値
    - `LEN` 音長、表記は `n+m` で n が `ln` の値、m が `l+m` の値
    - `VOL` 音量、表記は `n+m` で n が `Vn` の値、m が `V+m` の値
    - `EXP` エクスプレッション
    - `DETUNE` デチューン、表記は `n+m` で n が `Dn` の値、m が `D+m` の値
    - `XPOSE` トランスポーズ
    - `REP_NEST` リピートネストの深さ

- 拡張コマンド `Wn`
  - 相対エクスプレッションコマンド `(`/`)` の値を指定しなかったときのデフォルトを $n$ に指定する
  - 初期値は mucc との互換性のため 1
  - FM 音源や PSG/SSG 音源ドライバからの移植が楽になる
  - `W*m` と書くと `(n` / `)n` と書いたときの変位が $n \times m$ になる。`Wn` と併用可能。
- 音長拡張表記 `^`
  - 音符の長さをつなげて書けるようにする
  - いままで `a2&a4&a16` とか書いていたのが `a2^4^16` で済む
  - つないだ結果がクロックの上限 382 を超えるとエラーになる。このような時は後述の `a2&1&1&1&1` の記法を使う。
  - 他ドライバからの移植が楽になる
- コンパイル完了時に各パートの総クロックとループポイントまでのクロックを表示する
  - パートの同期ずれのデバッグに威力を発揮する

上記の拡張コマンドや表記は演奏データとしては書き出されないので、演奏データはパート拡張部分を除けば既存の muslib に完全互換です。

## mucc からの変更・修正

- `l` の初期値を 4 にした
  - mucc では 0 だったため、`l` を書く前に音長を省略した音符は音長 0 として扱われていた
  - 演奏データでは、音長は音符の前に置く 1 バイトの値で、クロック数をそのまま書き込む (1〜126。127 以上は `0x7F` に続けて書く)。直前の音符で音長を書き出していると、ここに 0 がそのまま書き込まれる。ところが `0x00` はパート終端のコマンドなので、演奏はそこで止まってしまう
  - 音長をまだ書き出していないとき (パートの先頭や `[`、`]` の直後) は何も書き出されず、muslib がその時点で持っている音長で演奏される。パートの先頭なら 1 クロックになる
- 音長が 1 クロック未満、または 382 クロックを超えたらエラーで中止する
  - `c%0` や、`l%-n` で音長の合計が 0 以下になった場合など。0 がそのまま書き込まれてパートが終わってしまったり、負の値が音符のバイトとして読まれたりしていた
  - 382 クロックを超える音長は演奏データで表せない。`c1&1&1&1` のようにタイでつなぐ
- 音域外の音符を `?` 命令で書き出す
  - 通常の音符で書けるのは o0c から o7b まで。これを超える音符は `?` 命令付き (1 バイト増える) で書き出して警告する
  - `?` 命令で書けるのは o-1c から o10g まで。それも超えたらエラーにする
  - o0 から `<` で下げたオクターブは o-1 として扱う。mucc では o255 になっていた
  - o8 以上の音符は、元の muslib では `@3`〜`@5` の音色で 1 オクターブ低く鳴ることがある
- `?` 命令のあとの音符に音長を書くと壊れたデータになっていたのを修正
- `L` でループしたときの不具合を修正
  - `L` の直後の音符が音長を省略していると、ループで戻ったときにパート末尾の音長で演奏されていた。必要なときはパート末尾に音長を書き出す
  - レガート (`&`) の状態も同様。パート末尾の `&` で `L` の直後の音につなぐ書き方もできる
  - パートの先頭に置いた `L` が無視されていた
- クロック計算の修正
  - リピート中に `:` を 2 つ以上書いても、抜けるのは最初の `:` だけだった。これはエラーにした (後述)
  - ドラムパターン中の音符と休符の数 (ステップ数) を数える。ドラムパターンの音符はそれぞれ呼び出したパートの音長を消費する。ドラムマクロの一覧にステップ数も表示する
- ドラムマクロ
  - 96 個を超えたらエラーで中止する
  - ドラムパターンは最初に呼び出したときにコンパイルするので、ドラムマクロ中で使うマクロ (`!name`) はそれより前に定義しておく
- パート名だけの行 (`A` など) と、値のない `#Title2` を受け付ける
- エラーを見つけた時点で中止し、演奏データを出力しない。これまで警告を出して続行していたもの、何も言わずに壊れたデータを出力していたものも、次のようにエラーにした
  - 未知のコマンド、未知の形式の行。これまではその行の残りを捨てていた。マクロの中で起きると、そのあとの行の演奏順も狂っていた
  - 定義されていないマクロやドラムマクロの呼び出し、マクロの再帰呼び出し (16 段まで)
  - マクロ、ドラムマクロ、`#Title` などのメタタグの再定義。どの定義が使われるかがわかりにくいため
  - パラメータの省略や不足 (`@` だけ、`E1,2`、`E220,,0,0` など)。これまでは前に使った値などのゴミが書き込まれていた
  - パラメータの範囲外。演奏データに 1 バイトで書くパラメータは、符号付きなら -128〜127、符号なしなら 0〜255 の範囲に収まらないとエラーにする。`D`、`_`、`(`、`)`、`v` の相対指定、`Z` の 1 つ目が符号付きで、ほかは符号なし。これまでは下位 8 ビットに切り詰めていた
    - `q` は 0〜100、`Q` は 0〜8 (pmml.txt のとおり)。`W` は 1〜127
  - `c0`、`l0`、`c97` のように、96 分音符より短い、または 0 の音長。これまでは警告して丸めていた
  - 対応する `[` のない `]`、リピートの外の `:`、同じリピート中の 2 つ目以降の `:`
  - 閉じていない `[` と `{`、`{` の中の `{`、対応する `{` のない `}`、音符が 2 つないか同じ音高どうしのポルタメント
  - リピートのネストが 8 段を超える場合。muslib はリピートとドラムパターンの呼び出しを合わせて 8 段までしか積めないので、ドラムパターンの呼び出しは 1 段、その中のリピートも数える
  - パートの終わりにある、音符の続かない `?`
  - 演奏データが 64KB を超える場合

## 削除した機能

- アセンブラ様表記のコンパイル（P/ECE開発環境添付の `jsbad.s` など）
- 出力データはバイナリファイルのみ、Cソースやアセンブラ形式出力はなし
- ~~音符なしでいきなり現れる数字~~
  - 直近の音符をその数字で鳴らす、という意味らしい
  - PMDで使っているので復活させた
  - `a1&1&1&1` のように使う。`a1^1^1^1` と比べて最大長制限がない
- パート中の `i` コマンド
  - 文中マクロ定義？
